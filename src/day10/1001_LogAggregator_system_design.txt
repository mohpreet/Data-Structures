	1) logging source
	2) mechanism to push the record to central non sql db
	3) scalable durable no sql db
	4) a ui to send queries

FRs

			structure of the collection will be dependent of the query contract.
		2) ability to query the logs using queries
			{
				logging_level:[info, debug, error]
				logging_pattern:{}
				[timestamp]
				[aggreation]
				[service name]
			}
		3) ability to visualize the logging patterns

			actual collections and give the data to ui [chart.js,grafana].
			Interation of the results of the saved queries and feeding data to the ui componnet will be happening some transaltor provided by the third party library or we have to code the same.
